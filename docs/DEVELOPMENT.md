# Разработка

Този документ съдържа насоки и правила за разработка и добавяне на нови функции към проекта Tab5 Touch Deck.

## Конвенции за писане на код

- **Език:** C (C11) за firmware-а, Python (3.11+) за host агента.
- **Стил на кода (C):** ESP-IDF стил (подобен на Linux kernel). Използвайте `snake_case` за променливи и функции. Макросите са с главни букви `UPPER_CASE`.
- **Стил на кода (Python):** PEP 8.
- **Коментари:** Документирайте сложната логика, особено при работа с хардуер, прекъсвания (interrupts) и FreeRTOS задачи.
- **LVGL:** Използвайте версии съвместими с LVGL 9.5.0.

## Добавяне на нови екрани

1. **Конфигурация:** Добавете новия екран и неговите бутони в `storage/config.json`.
2. **Парсване:** Уверете се, че парсерът във `firmware/main/` може да прочете новите полета, ако има такива.
3. **UI Логика:** Ако екранът изисква специфична логика (напр. динамични данни), създайте нов C файл и регистрирайте callback функциите за бутоните.
4. **Свързване:** Актуализирайте главния UI контролер, за да може да навигира до новия екран.

## Дебъгване

- **Сериен порт:** Поради използването на USB за HID, стандартният USB CDC може да не е наличен за конзолен изход по време на нормална работа, освен ако не се използва допълнителен USB-UART адаптер към съответните пинове.
- **Python Агент:** Стартирайте `agent.py` с допълнителни флагове (ако са имплементирани) за по-подробен изход (verbose mode).
- **JTAG:** За дълбок дебъг на ESP32-P4 може да се използва JTAG интерфейс, ако хардуерът го позволява.

## Логове

- Използвайте макросите `ESP_LOGI`, `ESP_LOGE`, `ESP_LOGW`, `ESP_LOGD` от ESP-IDF.
- В Python агента използвайте модула `logging` за записване на събития. Поддържайте логове за грешки при неоторизирани команди или проблеми с USB комуникацията.
